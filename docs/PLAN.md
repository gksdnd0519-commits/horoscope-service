# 별빛 운세 — 서비스 계획서

> 생년월일만 넣으면 내 별자리와 오늘의 운세, 궁합까지 한 화면에서 보는 무료 별자리 운세 웹 서비스

## 1. 배경과 목표

| 구분 | 내용 |
| --- | --- |
| 문제 | 기존 운세 사이트는 광고·유료 유도·메뉴가 많아 "오늘 내 운세"를 보기까지 단계가 길다. 모바일 화면에서 읽기 불편하다. |
| 목표 | 3초 안에 오늘의 운세를 보여주는 가볍고 깔끔한 모바일 우선 서비스 |
| 대상 | 출근·등교길에 가볍게 운세를 확인하는 20~30대, 친구와 궁합을 공유하며 노는 사용자 |
| 차별점 | ① 생년월일 입력 → 별자리 자동 판별 ② 날짜마다 바뀌는 오늘의 운세(항목별 점수) ③ 궁합을 링크로 공유 ④ 회원가입·결제 없음 |

## 2. 핵심 기능 (MVP v1.0)

| # | 기능 | 설명 | 우선순위 |
| --- | --- | --- | --- |
| F1 | 별자리 판별 | 생년월일(월/일) → 12별자리 자동 판별, 직접 선택도 가능 | 필수 |
| F2 | 오늘의 운세 | 총운·애정·금전·일/학업 4개 항목, 1~5점 별점 + 한 줄 메시지, 행운 색/숫자/아이템. 한국 날짜(KST) 기준으로 매일 바뀌고 같은 날 같은 별자리는 같은 결과 | 필수 |
| F3 | 별자리 프로필 | 성격·연애·직업·건강·행운요소 (자체 작성 콘텐츠) | 필수 |
| F4 | 별자리 궁합 | 두 별자리의 원소(불·흙·공기·물)와 황도 위치 관계로 궁합 점수와 설명 | 필수 |
| F5 | 공유 | `?sign=leo` 같은 URL로 결과 공유, 링크 복사 버튼 | 필수 |
| F6 | 다크 모드 | 시스템 설정을 따르는 밝은/어두운 테마 | 선택 |

### 범위 밖 (v1에서 하지 않음)
- 로그인·결제·서버·DB
- 출생 시간 기반 상승궁/하우스 계산 (v2 검토)
- 레퍼런스 사이트 문구의 재사용 (콘텐츠는 전부 자체 작성)

## 3. 사용자 흐름

```
첫 화면 ─ 생년월일 입력 or 별자리 아이콘 선택
   │
   ▼
결과 화면 ─ [오늘의 운세] [별자리 프로필] [궁합] 탭
   │                                   │
   └─ 공유 링크 복사                   └─ 상대 별자리 선택 → 궁합 결과
```

## 4. 기술 구성

| 항목 | 선택 | 이유 |
| --- | --- | --- |
| 프론트엔드 | HTML + CSS + 바닐라 JS (ES Modules) | 빌드 도구 없이 바로 배포, 가볍고 빠름 |
| 운세 생성 | 날짜+별자리를 시드로 한 결정적 난수 → 자체 문구 풀에서 조합 | 서버 없이 매일 바뀌는 운세 제공 |
| 테스트 | Node.js 내장 `node:test` | 별자리 경계일·운세 결정성 검증 |
| 배포 | GitHub Pages + GitHub Actions (`gh` CLI로 저장소 생성·배포) | 무료, push 하면 자동 배포 |
| 레퍼런스 수집 | Python + Firecrawl API | 경쟁 서비스 항목 구성 분석 |

## 5. 폴더 구조

```
horoscope-service/
├─ README.md                  실행·배포 방법
├─ docs/
│  ├─ PLAN.md                 서비스 계획서 (이 문서)
│  └─ REFERENCE.md            레퍼런스 분석 결과
├─ references/
│  ├─ crawler/crawl_conste.py Firecrawl 수집 스크립트
│  └─ raw/                    수집 원문 (git 제외, 로컬 전용)
├─ site/                      ← GitHub Pages로 배포되는 폴더
│  ├─ index.html
│  └─ assets/
│     ├─ css/style.css
│     └─ js/
│        ├─ zodiac.js         12별자리 데이터·판별 로직
│        ├─ fortune.js        오늘의 운세·궁합 생성 로직
│        └─ app.js            화면 렌더링·이벤트
├─ tests/zodiac.test.mjs      로직 단위 테스트
└─ .github/workflows/deploy.yml  Pages 자동 배포
```

## 6. 일정

| 단계 | 작업 | 산출물 |
| --- | --- | --- |
| 1 | 폴더 생성 | `horoscope-service/` |
| 2 | 계획 수립 | `docs/PLAN.md` |
| 3 | 폴더 구조 확정 | 위 5장 |
| 4 | 레퍼런스 수집·분석 | `references/`, `docs/REFERENCE.md` |
| 5 | MVP 개발 | `site/`, `tests/` |
| 6 | GitHub CLI로 배포 | GitHub Pages URL |

## 7. 이후 로드맵
